КОНТЕКСТ
Учебная компания продаёт офисную мебель (столы, кресла, шкафы), а также оказывает услуги доставки и сборки. Компания получает входящие заявки, часть обращений обрабатывается слишком долго: менеджеры вручную читают текст, выделяют важные данные, квалифицируют запрос и готовят ответ. Приложение должно ускорить эту работу. Все данные в проекте синтетические.

ЧТО СОБРАТЬ (ИНТЕРФЕЙС)
Простое веб-приложение на русском языке, одна страница:
- поле для текста заявки;
- кнопка «Обработать»;
- индикатор обработки;
- карточка результата;
- понятное сообщение при ошибке;
- три кнопки для подстановки тестовых заявок (тексты ниже).
Карточку показывать с понятными русскими названиями полей, а не как сырой JSON.

AI
- Для анализа заявки использовать настоящий GigaChat API. Не подменять анализ заглушками.
- Используй актуальный способ авторизации GigaChat API (проверь документацию).
- Данные доступа хранить в .env. Не включать их в клиентский код, логи и git.
- Создай .env.example с пустыми значениями и добавь .env в .gitignore.
- Не проси меня присылать секреты в чат.

ВХОД
Свободный текст заявки. В тексте могут быть: компания, имя, контакт, продукт, количество, бюджет, сроки. Любая информация может отсутствовать.

ВЫХОД
Структурированный результат:
- company — компания;
- summary — суть запроса;
- lead_type — целевой / нецелевой / неясно;
- key_data — известные данные;
- missing_data — чего не хватает;
- next_step — следующий шаг;
- reply_draft — черновик ответа;
- needs_human — нужен ли человек;
- human_reason — причина передачи человеку.

КРИТЕРИИ КВАЛИФИКАЦИИ
- Целевой: запрос относится к продукту или услуге компании и есть понятное намерение обсудить покупку.
- Нецелевой: запрос не относится к продукту или услуге компании.
- Неясно: информации недостаточно, чтобы уверенно определить тип лида.

ПРАВИЛА
- Не выдумывать данные. Если данных нет — писать «не указано».
- Отсутствующие важные данные добавлять в missing_data.
- Если информации недостаточно — задавать 1–2 ключевых уточняющих вопроса.
- Не обещать цены, сроки, скидки и другие условия, которых нет во входных данных.
- Жалобы, конфликты, угрозы отказа, требования возврата и нестандартные запросы передавать человеку.
- При передаче человеку формировать нейтральный черновик ответа без неподтверждённых обещаний.

ОГРАНИЧЕНИЯ
На этом этапе не делать: CRM, базу данных, авторизацию, мессенджеры, автоматический источник заявок.

КРИТЕРИЙ ГОТОВНОСТИ
Приложение запускается, принимает тестовую заявку, возвращает карточку со всеми полями, корректно обрабатывает полный, неполный и конфликтный сценарий, содержит README с инструкцией запуска.
